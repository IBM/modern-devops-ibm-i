Traditional IBM i vs modern DevOps workflows

In many traditional IBM i applications, business logic, 5250 user interface flow, and database access are tightly combined within the same programs. This design made perfect sense when applications were smaller and teams were centralized, but it makes change slower and riskier today.

Manual compile and promotion steps, dependence on organizational silo knowledge, and limited automation are common patterns, especially challenging when teams are under time pressure or when key experts are unavailable.

A modern approach doesn't require rewriting everything. The biggest shift is modularization: breaking large programs into service programs made of reusable procedures. This single architectural change improves testability, reduces risk, and enables reliable CI/CD pipelines. Complementing this, a datacentric or SQL-first approach moves data rules, such as keys, constraints, triggers, and views into the database itself, allowing application code to stay cleaner and easier to maintain. Updated tooling such as VS Code or RDi with IBM i extensions brings modern editing, integrated compile capabilities, and Git-based workflows to the platform. Once core logic is modular and datacentric, organizations can safely add APIs, REST/JSON interfaces, or refreshed UIs; doing these too early often leads to fragile integrations.

Key concepts

The traditional patterns

Business logic, UI flow (5250), and database access often live in the same programs. This made sense when apps were smaller, but it complicates change today.

Manual compile/promotion steps, dependence on organizational silo knowledge, and limited automation are common, and risky under time pressure.

The modern approach

Modularization: Split large programs into service programs with reusable procedures. This is the single biggest enabler for safer changes and pipelines.

Datacentric (SQL-first): Move data rules to the database (keys, constraints, triggers, views); keep programs thinner and easier to test.

Tooling upgrade: Use VS Code (or RDi) + IBM i extensions for editing, integrated compile, and Git.

APIs & interfaces: Add REST/JSON or UI refacing after the core is modular and datacentric; doing it earlier often fails.

Quick Win

Identify one big program you work with often. Extract a small, low-risk piece — such as a calculation — into a service program and call it from the original. That's modernization, no UI changes required.
